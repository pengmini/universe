# 소통의 우주 (Communication Universe)

학생들의 학급 내 상호작용을 3D 우주로 시각화하는 교육용 웹앱 프로토타입.
글을 올리면 **위성 행성**이 생기고, **공감은 숨은 별**로, **댓글은 위성을 도는 작은 구**로 쌓입니다.

> **Phase 0 프로토타입입니다.** 데이터는 브라우저 메모리에만 있고, 새로고침하면 초기화됩니다.
> 실시간 동기화(Firebase) 연동은 아래 «다음 단계»를 참고하세요.

## 써보기

| 하는 일 | 결과 |
|---|---|
| 우측 상단 **나는** 에서 이름 선택 | 그 학생으로 활동합니다 |
| **전통놀이 / 음악 취향** 탭에서 글 올리기 | 해당 주제 행성 주위에 내 위성이 생깁니다 |
| 친구 글에 **공감** | 그 위성 주위에 **숨은 별** 하나 추가 |
| 친구 글에 **댓글 쓰기** → 내용 입력 → 등록 | 그 위성을 도는 **작은 구** 하나 추가 |
| **단소 도움** 탭에서 친구 이름 클릭 | 그 친구의 도움 횟수 +1, 숨은 별 +1 |
| 위성에 **마우스 올리기** | 이름·내용 툴팁 + 그 위성의 숨은 별이 환하게 켜집니다 |
| **댓글 구**에 마우스 올리기 | 누가 뭐라고 썼는지 툴팁에 보입니다 |
| **행성** 클릭 | 그 행성계의 회전이 멈춥니다 (다시 누르면 재개) |
| 우하단 **랜덤 / 직접 선택** → **숨은 태양 띄우기** | 태양 3개가 떠오르고 연결선이 뻗습니다 |
| 우하단 **참여 적은 친구** | 참여가 저조한 학생 표시를 켜고 끕니다 |
| 캔버스 **드래그 / 휠** | 360° 회전 / 줌 |
| **전자칠판 모드** | 대시보드를 접고 우주만 전체 화면으로 |

교실 앞 전자칠판에서는 전자칠판 모드로 띄워두고, 학생들은 크롬북에서 대시보드로 접속하는 구성을 상정했습니다.

## 시각 규칙

| 요소 | 정체 | 크기 · 동작 |
|---|---|---|
| **주제 행성** (중앙 3개) | 대주제 | 위성이 늘수록 커지고 자체 발광 증가 |
| **위성 행성** | 학생이 올린 글 | 상호작용이 많을수록 크고 밝고 공전이 빨라짐 |
| **숨은 별** | 공감 · 단소 도움 | 위성 지름의 **1/2**. 평소 투명도 16%, 호버 시 92%. **공전하지 않고 고정** |
| **댓글 구** | 댓글 (내용 포함) | 위성 지름의 **1/3**. 위성을 6~15초 주기로 **공전**. 호버 시 1.3배 |
| **숨은 태양** | 마무리 연출 | 위성보다 훨씬 큼. 이름표와 연결선이 함께 나타남 |
| **분홍 별** (바깥) | 참여가 적은 학생 | 토글로 끄면 3D 씬에서 완전히 사라짐 |

주제별 색 계열 — 전통놀이(붉은), 음악 취향(푸른), 단소 도움(보라).
행성 표면은 같은 계열 2~3색을 섞은 마블 텍스처를 캔버스로 런타임 생성해 입힙니다.

### 규칙 상세

- **공감과 댓글은 각각 한 번씩** 누를 수 있습니다. 자기 글에는 둘 다 불가.
- **별 수는 공감만** 올립니다. 댓글은 별도로 셉니다.
- **단소 도움 주제**에서 위성은 *도움을 준 친구*, 주변 숨은 별은 *도움을 받은 친구*입니다.
- **참여가 적은 학생** 기준 = `올린 글 + 준 상호작용 + 받은 상호작용 ≤ 3`
  (코드의 `QUIET_MAX` 상수 한 줄로 조정)
- **숨은 태양**은 우주 전체의 숨은 별·댓글 구에서 뽑습니다. 같은 학생이 두 번 뽑히지 않으며,
  어느 위성의 어떤 별이 될지는 무작위입니다. 교사가 직접 세 명을 지정할 수도 있습니다.

## 구조

```
index.html        전부 여기 들어 있습니다 (마크업 · 스타일 · 3D 로직)
README.md
```

- **3D**: [Three.js r128](https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js) (CDN, UMD)
- **폰트**: Google Fonts — Jua, IBM Plex Sans KR, IBM Plex Mono
- 그 외 의존성 없음. 텍스처는 전부 `<canvas>`로 런타임 생성하므로 이미지 파일이 없습니다.

### 주요 함수

| 함수 | 하는 일 |
|---|---|
| `hashStr(str)` / `bits(h, sh, mod)` | 부호 없는 32비트 해시와 비트 추출 (아래 «개발 노트» 필독) |
| `marbleTex(mix)` | 주제 색 2~3개를 섞은 마블 텍스처 생성 |
| `nameSprite(text, color, px)` | 캔버스로 글자를 그려 3D에 띄우는 이름표 |
| `buildSats()` | `sats` 배열을 3D 오브젝트로 재구성 (데이터 변경 시 호출) |
| `buildActs(sa, t)` | 공감 → 숨은 별 스프라이트, 댓글 → 작은 구 메시 |
| `buildQuiet()` | 참여가 적은 학생을 바깥 궤도에 배치 |
| `starPool()` / `fireSuns()` | 태양 후보를 학생별로 묶고 3명을 선정 |
| `frame(now)` | 매 프레임 공전·크기·밝기·호버·정지 갱신 |
| `renderPanes()` | 대시보드 3개 탭 다시 그리기 |

### 데이터 모델 (현재: 메모리)

```js
sats = [{
  id:      "s1",
  topic:   "t1",                 // t1 전통놀이 · t2 음악 · t3 단소도움
  student: "민준",
  content: "딱지치기",            // t3는 도움 횟수 문자열
  acts: [
    { from: "서연", type: "like" },
    { from: "지우", type: "comment", text: "나도 그거 좋아해!",
      _orb: { rk, ang, spd, incl, node } },   // 댓글 구의 궤도 상태
    { from: "하윤", type: "help" },
  ]
}]
```

> `_orb`를 **3D 오브젝트가 아니라 데이터 쪽에** 붙여 둔 이유가 있습니다.
> 상호작용이 생길 때마다 `buildSats()`가 3D를 통째로 다시 만드는데, 궤도 각도를
> 메시에 두면 모든 댓글 구가 초기 각도로 **한꺼번에 순간이동**합니다.

## 개발 노트 — 반드시 읽고 손대세요

### `>>` 대신 `>>>`

궤도 속도·반지름을 해시 비트에서 뽑을 때 **부호 있는 시프트(`>>`)를 쓰면 안 됩니다.**
32비트 값의 최상위 비트가 켜져 있으면 음수가 나오고, 자바스크립트는 `음수 % n`도 음수입니다.

```js
const h = 2445500455;
h >>  22   // -441  ← 이러면 spd가 0 근처로 상쇄되어 '공전하지 않는' 천체가 생긴다
h >>> 22   //  583
```

실제로 이 버그로 **댓글 17개 중 10개, 위성 22개 중 6개가 멈춰 있었습니다.**
지금은 `bits(h, shift, mod)` 헬퍼 하나로 통일해 항상 0 이상이 나오도록 했습니다.

### 해시에 고유값을 충분히 섞기

이전 코드는 `(k+1)*상수 + sa.id.length*97`을 썼는데, **id의 길이**만 반영해서
`s1`과 `s5`가 같은 해시를 냈습니다. 그 결과 댓글 17개가 궤도 7가지만 나눠 쓰며
여러 위성에서 똑같이 움직였습니다. 지금은 `hashStr(sa.id + "#" + k)`로 id 전체를 섞습니다.

### 궤도 반지름은 부모 크기에 비례시키기

위성 궤도를 고정값으로 두면, 글이 쌓여 주제 행성이 커졌을 때 **위성이 행성 속에 파묻힙니다.**
지금은 `행성 반지름 × 1.62 + 여유분`으로 계산합니다. 댓글 구도 같은 방식으로
`위성 반지름 × (1.95 ~ 3.05)`를 씁니다.

## 다음 단계

### 1. Firebase 실시간 동기화

데이터 모양이 PRD의 Firestore 구조와 그대로 맞습니다.

```
topics/{topicId}          title, type, total_interactions
satellites/{satId}        topic_id, student_name, content, interaction_count
interactions/{id}         target_satellite_id, from_student_name, type, text, created_at
```

붙이는 지점은 네 곳입니다.

```js
// ① 읽기 — sats 배열만 갈아끼우고 buildSats() 호출
onSnapshot(collection(db, "satellites"), snap => {
  sats = snap.docs.map(d => ({ id: d.id, ...d.data() }));
  buildSats(); renderPanes(); stats();
});

// ② 글 올리기      — [data-post] 핸들러의 sats.push() 자리
// ③ 공감           — [data-act]  핸들러의 acts.push() 자리
// ④ 댓글 등록      — [data-send] 핸들러의 acts.push() 자리
await addDoc(collection(db, "interactions"), { target_satellite_id, from_student_name, type, text });
```

**중복 방지는 문서 ID로 거세요.** Firestore에는 UNIQUE 제약이 없지만, `create`는
문서가 이미 있으면 실패합니다.

```
interactions/{satId}__{fromUid}__{type}    ← 같은 사람이 같은 글에 공감 두 번 못 함
```

집계(`interaction_count`) 갱신은 Cloud Functions 트리거로 옮기고, 보안 규칙에서
클라이언트 쓰기를 막으세요.

### 2. React Three Fiber 이관

`frame()` 안의 갱신 로직이 그대로 `useFrame`으로 들어갑니다. 위성 하나가 컴포넌트 하나가
되고, 호버는 `onPointerOver`로 대체됩니다. 이 프로토타입을 순수 Three.js로 짠 이유는
R3F의 UMD 빌드를 CDN으로 불러올 수 없는 실행 환경 제약 때문이며, 로직은 그대로 옮겨집니다.

### 3. 후처리 블룸

지금 발광은 가산합성(additive) 스프라이트를 겹쳐 흉내 낸 것입니다.

```bash
npm i @react-three/postprocessing
```

```jsx
<EffectComposer>
  <Bloom intensity={0.9} luminanceThreshold={0.25} mipmapBlur />
</EffectComposer>
```

### 4. 폰트

PRD가 요청한 프리텐다드는 Google Fonts에 없어 **Jua**로 대체했습니다.
자체 호스팅하려면 [Pretendard](https://github.com/orioncactus/pretendard)를
`public/fonts/`에 넣고 `@font-face`로 선언하세요.
